### 2. Переменные окружения (ENV)

#### Префикс ANUBIS_

Все переменные окружения должны использовать префикс `ANUBIS_`. Viper автоматически удаляет этот префикс при поиске соответствий с конфигурацией.

**Пример:**
- ENV переменная: `ANUBIS_POSTGRES_PASSWORD=my_secret_password`
- Viper сопоставляет с: `postgres.password`

#### Правила преобразования имен

Viper автоматически преобразует имена по следующим правилам:

| YAML путь | ENV переменная |
|-----------|----------------|
| `app.ip` | `ANUBIS_APP_IP` |
| `postgres.user` | `ANUBIS_POSTGRES_USER` |
| `jwt.access_token_secret` | `ANUBIS_JWT_ACCESS_TOKEN_SECRET` |

#### Особые случаи

**Версия приложения:**
```bash
APP_VERSION=1.2.3  # Без префикса ANUBIS_!
```

**Секреты OAuth провайдеров:**
```bash
ANUBIS_LIST_SERVICES_CHANKI_PROVIDER_OAUTH_GOOGLE_CLIENT_SECRET=google_secret_123
ANUBIS_LIST_SERVICES_CHANKI_PROVIDER_OAUTH_YANDEX_CLIENT_SECRET=yandex_secret_456
```

## Приоритеты конфигурации

Настройки применяются в следующем порядке приоритета (от высшего к низшему):

1. **Переменные окружения** (с префиксом `ANUBIS_`)
2. **YAML-файл** (базовая конфигурация)
3. **Значения по умолчанию** в коде

## Примеры использования

### Локальная разработка

```bash

go run main.go
```


## Отладка конфигурации

Для просмотра итоговой конфигурации используйте метод:

```go
    config.PrintConfigJSON()
```

Это выведет полную конфигурацию в формате JSON, включая все переопределения из ENV переменных.

## Безопасность

- Секретные данные (пароли, ключи) должны передаваться только через ENV переменные
- YAML-файл может содержать тестовые/разработческие значения
- В продакшене все секреты должны быть в Kubernetes Secrets / Docker Secrets
- Никогда не коммитьте реальные секреты в YAML-файлы
